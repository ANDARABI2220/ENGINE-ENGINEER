# معماری جامع رابط کاربری ۶۰ فریم بر ثانیه و بهینه‌سازی عملکرد سامانه ساختمانی AfghanaBuild
## AfghanaBuild 60 FPS Stable UI Architecture & Performance Specification

این سند، مرجع مهندسی و فنی پیاده‌سازی رابط کاربری با نرخ پایدار **۶۰ فریم بر ثانیه (60 FPS)**، مدیریت پردازش لایه‌های سخت‌افزاری GPU، و سیستم واکنش تعاملی (Micro-interactions) بدون لگ برای تمام دستگاه‌های دسکتاپ، تبلت و تلفن‌های همراه مهندسین سازمان است.

---

### ۱. اصل طلایی بودجه ۱۶.۶ میلی‌ثانیه‌ای (16.6ms Frame Budget)
برای اجرای یک انیمیشن نرم و با نرخ ۶۰ هرتز، مرورگر باید هر فریم را در کمتر از ۱۶.۶ میلی‌ثانیه آماده و تحویل دهد:
$$\text{Frame Budget} = \frac{1000\text{ ms}}{60\text{ frames}} \approx 16.66\text{ ms}$$

اگر اجرای جاوااسکریپت، محاسبه مجدد چیدمان (Layout) یا رنگ‌آمیزی مجدد (Paint) حتی ۱ میلی‌ثانیه بیش از این مقدار زمان ببرد، فریم مربوطه از دست می‌رود و پدیده لکنت یا پرش (Jank) رخ می‌دهد.

---

### ۲. خط لوله رندرینگ مرورگر و اجتناب از Reflow و Repaint
چرخه رندر در مرورگرهای وب به شرح زیر است:
1. **JavaScript / React State**: بروزرسانی متغیرها، رویدادهای کاربر و واکنش کامپوننت‌ها
2. **Style Calculation**: محاسبه قوانین اعمال‌شده CSS برای هر المان DOM
3. **Layout (Reflow)**: محاسبه موقعیت مکانی و ابعاد هندسی (بسیار سنگین برای CPU)
4. **Paint**: پر کردن پیکسل‌ها، رنگ متن‌ها و سایه‌ها در لایه‌های رندرینگ
5. **Compositing (GPU)**: لایه‌بندی و ادغام تصاویر در پردازنده گرافیکی (بسیار سریع و سبک)

#### قانون معماری ۶۰ فریم در AfghanaBuild:
> **کلیه ترنزیشن‌ها و انیمیشن‌های سامانه منحصراً در فاز ۵ (Compositing) اجرا می‌شوند.**
> هیچ انیمیشنی مجاز به فعال‌سازی فاز ۳ (Layout) یا فاز ۴ (Paint) نیست.

### ۳. ماتریس جامع ویژگی‌های مجاز در برابر ویژگی‌های پرهزینه

| ویژگی CSS | فازهای درگیر | وضعیت استفاده | علت فنی و استاندارد جایگزین |
| :--- | :--- | :--- | :--- |
| `transform: translate3d(x, y, 0)` | **فقط Composite** | ✅ **الزامی** | جابجایی المان‌ها بدون ایجاد مجدد چیدمان (Reflow) |
| `transform: scale(x)` | **فقط Composite** | ✅ **الزامی** | کوچک/بزرگ‌نمایی کارت‌ها و دکمه‌ها در هاور و لمس |
| `opacity: 0 <-> 1` | **فقط Composite** | ✅ **الزامی** | محو و نمایان شدن دیالوگ‌ها، توست‌ها و تب‌ها |
| `will-change: transform, opacity` | پیش‌تخصیص حافظه GPU | ✅ **توصیه شده** | ارتقای لایه به Graphics Layer مستقل پیش از انیمیشن |
| `backface-visibility: hidden` | بهینه‌سازی لایه | ✅ **الزامی** | جلوگیری از لرزش لبه‌های متن و پیکسلی‌شدن |
| `top`, `left`, `right`, `bottom` | Layout + Paint + Comp | ⛔ **اکیداً ممنوع** | محاسبه مجدد هندسه کل صفحه (Layout Thrashing) |
| `width`, `height` | Layout + Paint + Comp | ⛔ **اکیداً ممنوع** | به جای آن از `scaleX` و `scaleY` استفاده شود |
| `margin`, `padding` | Layout + Paint + Comp | ⛔ **اکیداً ممنوع** | باعث فشرده‌شدن و تکان خوردن المان‌های مجاور می‌گردد |
| `box-shadow` (انیمیشن پیوسته) | Paint + Composite | ⚠️ **محدود** | به جای تغییر اندازه بلور، از سایه ثابت یا تغییر Opacity لایه سایه استفاده شود |

### ۴. معماری فیدبک لمسی و کلیک (Haptic & Tactile Interactions)
بر اساس پاسخ‌های دریافتی از اعتبارسنجی نیازمندی‌ها، سبک بصری **مهندسی مدرن با ترنزیشن‌های سریع و بهینه** و **فیدبک ملایم مقیاس و سایه** بر روی المان‌ها پیاده‌سازی شده است:

#### ۴-۱. دکمه‌های کنشی (`.ab-btn-primary`, `.ab-btn-secondary`):
- **Hover:** انتقال ملایم ۱ میلی‌متری رو به بالا `translateY(-1px)` و تقویت سایه با انتشار کهربایی
- **Active (کلیک یا لمس انگشت):** مقیاس فشردگی ملایم `scale(0.97)` با سرعت ۱۶۰ میلی‌ثانیه و منحنی `cubic-bezier(0.2, 0, 0, 1)`
- **Ripple Effect:** انیمیشن انتشار موج شفاف سفید برای تصدیق قطعی دریافت لمس کاربر

#### ۴-۲. کارت‌های تعاملی و داشبورد (`.ab-card-interactive`, `.ab-card-interactive-accent`):
- **Hover:** بالا آمدن ملایم ۳ پیکسلی با `translateY(-3px) scale(1.008)` و نورپردازی ملایم حاشیه طلایی
- **Active:** فشرده‌سازی ارتجاعی `scale(0.985)` متناسب با موبایل و دسکتاپ
- **Focus-visible:** حلقه فوکوس ۲ پیکسلی کهربایی با فاصله ۲ پیکسل برای کاربرانی که با کیبورد ناوبری می‌کنند

### ۵. بهینه‌سازی‌های اختصاصی کارگاهی و محیط موبایل (Mobile & Field Engineering)
مهندسین کارگاه با شرایط محیطی سخت و سرعت اینترنت متغیر کار می‌کنند:
1. **حذف تاخیر ۳۰۰ میلی‌ثانیه‌ای (Zero Tap Delay):** اعمال سرتاسری `touch-action: manipulation;` بر روی کلیه عناصر قابل لمس جهت غیرفعال‌سازی تاخیر تشخیص دابل‌تپ در مرورگرهای موبایل.
2. **غیرفعال‌سازی باکس خاکستری پیش‌فرض:** استفاده از `-webkit-tap-highlight-color: transparent;` برای حفظ ظاهر مهندسی سیستم.
3. **ارگونومی ابعاد لمسی (Touch Targets):** حفظ حداقل ابعاد ۴۴×۴۴ پیکسل بر اساس استاندارد دسترسی‌پذیری، تا حتی هنگام استفاده از دستکش کارگاهی المان‌ها به راحتی فشرده شوند.
4. **Passive Event Listeners:** کلیه رویدادهای اسکرول و تاچ با فلگ `{ passive: true }` ثبت می‌شوند تا نخ اصلی رندر مرورگر قفل نگردد.

### ۶. چک‌لیست اندازه‌گیری و بنچمارک عملکرد با ابزارهای تخصصی

#### الف) تست با Chrome DevTools Performance Panel:
1. مرورگر کروم را باز کرده و با کلیدهای `Ctrl+Shift+I` ابزار توسعه‌دهنده را باز کنید.
2. به زبانه **Performance** بروید.
3. گزینه **CPU** را روی حالت **4x Slowdown** (شبیه‌سازی دستگاه موبایل متوسط کارگاهی) تنظیم کنید.
4. دکمه ضبط را بزنید و در سامانه بین تب‌ها جابجا شده و روی کارت‌ها و دکمه‌ها کلیک کنید.
5. نتیجه باید نمودار فریم‌های سبز یکنواخت در رنج ۵۸ الی ۶۰ فریم بر ثانیه بدون هشدارهای قرمز Long Task باشد.

#### ب) تست با Rendering Panel (Paint Flashing):
1. در پنل بالا کلیدهای `Ctrl+Shift+P` را زده و دستور `Show Rendering` را وارد کنید.
2. گزینه **Paint Flashing** را روشن نمایید.
3. هنگام اسکرول یا هاور روی کارت‌ها، صفحه نباید با رنگ سبز مداوم فلش بزند؛ تنها لایه‌های مجزا با حداقل درگیری کامپوزیت می‌شوند.

#### ج) نمایشگر زنده Frame Rate Meter:
1. دستور `Show Frame Rate Meter` را در کنسول اجرا نمایید.
2. نرخ ۶۰ FPS پایدار و استفاده کم GPU را در گوشه سمت چپ بالای نمایشگر ارزیابی فرمایید.

### ۷. استانداردهای دسترسی‌پذیری و کاهش حرکت (Reduced Motion)
مطابق با استاندارد **WCAG 2.1 AA/AAA**، کاربرانی که در تنظیمات سیستم‌عامل خود (Windows, macOS, iOS, Android) گزینه **Reduce Motion** را فعال کرده‌اند، سیستم به طور خودکار مدت زمان انیمیشن‌ها را به `0.01ms` کاهش داده و از هرگونه حرکت بصری که موجب سرگیجه یا حواس‌پرتی شود جلوگیری می‌نماید:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
